📚 Introducción

Práctica: Cuantización de Modelos de Lenguaje

Fecha: 23 de enero de 2026

Objetivo: Convertir un modelo de alta precisión (FP16) a formato cuantizado (Q3) para reducir tamaño y mejorar velocidad

¿Qué es la cuantización?

La cuantización es el proceso de reducir la precisión numérica de los parámetros de un modelo de lenguaje para que ocupe menos espacio y sea más rápido, con mínima pérdida de rendimiento.

Imagina que el conocimiento de un modelo está almacenado en números con muchos decimales, como 7.123456789. La cuantización redondea ese número a 7.12 o incluso a 7. El número es menos preciso, pero sigue representando casi el mismo valor, es mucho más fácil de almacenar y más rápido para hacer cálculos.

📖 Teoría de la Cuantización

Concepto central

La cuantización de un LLM consiste en reducir el número de bits necesarios para representar cada peso del modelo.

Normalmente, los modelos se entrenan usando números de alta precisión de 32 bits (FP32). La cuantización convierte estos pesos a formatos de menor precisión:

  • 32 bits (FP32): Precisión completa (usado en entrenamiento)
  • 16 bits (FP16): Media precisión
  • 8 bits (INT8): Cuantización moderada
  • 4 bits (INT4): Muy popular para ejecución local
  • 3 bits (INT3): Cuantización agresiva

💡 Punto clave: No se cambia el conocimiento fundamental del modelo, solo la precisión con la que se almacena y procesa cada pieza de ese conocimiento.

Beneficios prácticos

💾 Reducción de tamaño

Un modelo de 28 GB en FP32 puede reducirse a 4 GB en INT4 (reducción del 85%).

🧠 Menor consumo RAM/VRAM

Modelos que requerían 24 GB ahora caben en GPUs de 8 GB.

�?Inferencia más rápida

Cálculos con enteros son más rápidos que con flotantes de 32 bits.

🧑‍�?Democratización

Permite ejecutar modelos potentes en hardware consumer sin servidores cloud.

El trade-off: precisión vs eficiencia

⚠️ Coste a pagar: Al simplificar los pesos, el modelo puede volverse ligeramente "menos inteligente". Puede que no capte matices tan sutiles o cometa pequeños errores que la versión FP32 no cometería.

El punto óptimo: Las técnicas modernas (GGUF, AWQ) buscan el mejor equilibrio entre compresión/velocidad y mínima pérdida de precisión. Para la mayoría de usos, una cuantización a 4 bits (Q4_K_M) es casi indistinguible del modelo original.

Tipos de cuantización en GGUF

Tipo Bits Tamaño relativo Calidad Uso recomendado
F16 16 100% Máxima Referencia
Q8_0 8 ~50% Muy alta Sin pérdidas notables
Q5_K_M 5 ~35% Alta Excelente equilibrio
Q4_K_M 4 ~25% Buena Estándar de oro
Q3_K_M 3 ~19% Aceptable Memoria muy limitada
Q2_K 2 ~12% Baja Solo experimentación

Nomenclatura GGUF

Las letras Q4_K_M se refieren al nivel de cuantización:

  • Q: Quantization (Cuantización)
  • 4: Número de bits por parámetro (menos bits = más ligero pero menos inteligente)
  • K: Técnica moderna de compresión (K-quants)
  • M: Ajuste del algoritmo
    • S (Small): Más compresión
    • M (Medium): Equilibrado
    • L (Large): Más calidad

💡 Nota: A partir de Q8, no se usa la serie K (ej: Q8_0) porque a ese nivel de calidad no hace falta usar técnicas complejas de compresión.

🛠�?Práctica Realizada

Objetivo

Convertir el modelo Phi-3-mini-4k-instruct de Microsoft desde formato FP16 (alta precisión) a formato GGUF cuantizado a 3 bits (Q3_K_M).

Herramientas necesarias

  • Python 3.x instalado
  • Git y git-lfs
  • Repositorio llama.cpp
  • ~15 GB de espacio libre en disco

Paso 1: Preparar el entorno

# Crear carpeta del proyecto
mkdir ejercicio-cuantizacion
cd ejercicio-cuantizacion

# Clonar llama.cpp
git clone https://github.com/ggerganov/llama.cpp.git

# Crear entorno virtual
python -m venv venv

# Activar entorno (Windows)
venv\Scripts\activate

# Activar entorno (Linux/macOS)
source venv/bin/activate

# Instalar dependencias
pip install -r llama.cpp/requirements.txt

Paso 2: Descargar el modelo original

# Asegurarse de tener git-lfs instalado
# Descargar desde: https://git-lfs.github.com/

# Clonar el modelo (varios GB)
git clone https://huggingface.co/microsoft/Phi-3-mini-4k-instruct

⚠️ Atención: La descarga puede tardar mucho tiempo dependiendo de tu conexión. El modelo original ocupa ~7 GB.

Paso 3: Conversión y cuantización

Este es el paso central. Ejecutamos el script que lee el modelo original y genera el archivo GGUF cuantizado:

python llama.cpp/convert-hf-to-gguf.py ./Phi-3-mini-4k-instruct/ --outtype q3_k_m --outfile phi-3-mini-q3.gguf

Desglose del comando:

  • python llama.cpp/convert-hf-to-gguf.py - Script de conversión
  • ./Phi-3-mini-4k-instruct/ - Carpeta con modelo original
  • --outtype q3_k_m - Tipo de cuantización (3 bits, K-quants, Medium)
  • --outfile phi-3-mini-q3.gguf - Nombre del archivo final

Opciones de cuantización alternativas

# Sin cuantización (16 bits) - Máxima calidad
--outtype f16

# 8 bits - Alta calidad, casi sin pérdidas
--outtype q8_0

# 5 bits - Excelente punto intermedio
--outtype q5_k_m

# 4 bits - Estándar de oro (más común)
--outtype q4_k_m

# 3 bits - Lo que usamos (agresivo pero viable)
--outtype q3_k_m

# 2 bits - Extremadamente comprimido
--outtype q2_k

💡 Aprendizajes

🔧 Técnicos

  • La cuantización es compresión con pérdida: Similar a convertir un FLAC a MP3. Se pierde algo de información pero el resultado sigue siendo muy útil.
  • Q3 es agresivo pero viable: Reducir de 16 bits a 3 bits (5.3x menos precisión) resultó en 53% de reducción de tamaño. El modelo Q3 genera respuestas más concisas que el FP16.
  • GGUF es el estándar actual: Formato optimizado para ejecución en CPUs y GPUs consumer, reemplazando formatos anteriores como GGML.
  • llama.cpp es multiplataforma: Funciona en Windows, Linux, macOS e incluso dispositivos móviles con las librerías adecuadas.
  • El proceso es determinístico: Cuantizar el mismo modelo con los mismos parámetros siempre produce el mismo resultado (mismo tamaño, mismo hash).

📚 De proceso

  • Importancia del entorno virtual: Aislar las dependencias evita conflictos con otras versiones de librerías Python en el sistema.
  • Git LFS es esencial: Los modelos son archivos enormes (>1GB). Git normal no puede manejarlos, necesita Git Large File Storage.
  • Paciencia en descargas: 7 GB pueden tardar mucho. Siempre verificar espacio en disco antes de empezar (mínimo 15 GB libres para tener margen).
  • Validación del resultado: Siempre probar el modelo cuantizado en LM Studio u otra herramienta antes de borrar el original.
  • Documentar fechas: Las propiedades del archivo muestran cuándo se creó cada versión, útil para auditoría.

🎯 Prácticos

  • Q4_K_M es el punto dulce: Para la mayoría de usos, Q4 ofrece mejor equilibrio que Q3. Q3 es útil solo si la RAM/VRAM es muy limitada.
  • No todo modelo cuantiza igual: Modelos más grandes (70B+) toleran mejor la cuantización agresiva que modelos pequeños (3B-7B).
  • Caso de uso importa: Para chatbots generales, Q3 puede ser suficiente. Para tareas de razonamiento complejo o código, mejor Q4 o Q5.
  • Cuantizar != Fine-tuning: La cuantización no mejora el modelo, solo lo hace más eficiente. El conocimiento sigue siendo el mismo.
  • FP16 más verboso que Q3: La cuantización puede afectar ligeramente el estilo de las respuestas, haciéndolas más concisas.

�?Mejores prácticas

  1. Empezar con Q4_K_M: Es el estándar. Solo ir a Q3 si realmente necesitas ahorrar espacio
  2. Mantener el original: No borrar el modelo FP16 hasta verificar que el cuantizado funciona bien
  3. Comparar perplejidad: Usar métricas objetivas para medir degradación de calidad, no solo pruebas subjetivas
  4. Documentar configuración: Anotar qué comando exacto usaste para poder replicarlo después
  5. Nombrar archivos claramente: Incluir el tipo de cuantización en el nombre (ej: phi-3-mini-q3.gguf)

📢 Recomendación final

Para futuros proyectos de cuantización:

  • Uso general: Q4_K_M es el mejor equilibrio
  • Hardware limitado: Q3_K_M como se hizo aquí
  • Máxima calidad: Q5_K_M o Q8_0
  • Experimentación: Probar Q2_K para ver los límites

La cuantización es una técnica fundamental para democratizar el acceso a modelos de IA potentes, permitiendo que se ejecuten en hardware consumer sin sacrificar demasiada capacidad.
